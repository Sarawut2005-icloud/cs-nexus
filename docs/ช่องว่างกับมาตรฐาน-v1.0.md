## 1. ข้อสรุปที่ต้องรู้ก่อนอย่างอื่น

**สถาปัตยกรรมการยืนยันตัวตนของเราสร้างบนสัญญาที่ถูกยกเลิกไปแล้ว**

`docs/auth-contract.md` ของมาตรฐานขึ้นต้นด้วยประโยคนี้:

> เอกสารนี้แทนที่ฉบับ OAuth2/Gateway เดิมทั้งฉบับ
> ฉบับก่อนหน้าอธิบายสถาปัตยกรรมที่ยังไม่มีจริง (API Gateway, `/oauth/token`, authorization code)

ฉบับที่ถูกแทนที่ คือฉบับที่ระบบเราสร้างตามมาทั้งหมด สิ่งที่กลับด้าน:

| เรื่อง | ที่เราทำ (ตามฉบับเก่า) | ที่ v1.0 บังคับ |
| --- | --- | --- |
| ตรวจลายเซ็น JWT | **ห้ามตรวจ** เชื่อ Gateway | **ต้องตรวจเอง** ด้วย jose + JWKS + `kid` ครบ 8 ขั้น |
| ตัวตนมาจากไหน | header `X-User-Id` | claim `sub` ที่ผ่านการตรวจลายเซ็นแล้ว |
| custom header | เป็นแหล่งความจริง | **ห้ามเชื่อเด็ดขาด** (ข้อ 6 และข้อห้ามข้อ 7) |
| API Gateway | มี | **ไม่มี** และยังไม่มีแผนจนถึง v2.0 |

`subsystem.yaml` ของเราประกาศไว้ว่า `verifies_jwt_signature: false`
ซึ่งตอนนี้กลายเป็น **การประกาศว่าเราละเมิดกฎ SEC-04** ไม่ใช่การประกาศว่าทำตามกฎ

นี่ไม่ใช่เรื่องที่ปรับนิดหน่อยแล้วผ่าน — ต้องเขียนชั้น auth ใหม่ทั้งชั้น

## 3. ปัญหาที่ลึกที่สุด — เราจะไม่มี `username` ให้ใช้อีกต่อไป

ทั้งระบบของเราใช้ `username` เป็นคีย์ตัวตน: เป็น primary key ของ
`subsystem_members`, `profile_cache` และเป็นคอลัมน์ในเกือบทุกตาราง

แต่ `data-dictionary.md` ข้อ 1.2 บอกว่า:

> `username` — มีในฐานข้อมูล Core Hub แต่ **ไม่อยู่ใน token** ·
> ดึงได้เฉพาะผ่าน `GET /api/v1/users/:id` ซึ่งต้องมี permission

token มีแค่ `sub` · `email` · `role` · `sid` เท่านั้น

**นี่คือข้อเท็จจริงเชิงกลไก ไม่ใช่เรื่องกฎการตั้งชื่อ** — ต่อให้ไม่มี linter
สักตัว เราก็จะไม่ได้รับค่า `username` มาตั้งแต่แรกอยู่ดี ระบบจึงต้องเปลี่ยน
คีย์ตัวตนไปเป็น `core_user_id` (ค่า `sub` เช่น `user-002`)

ขนาดงานที่วัดได้:

| ของ | จำนวน |
| --- | --- |
| ไฟล์ backend ที่อ้าง `username` | 46 |
| ไฟล์ frontend ที่อ้าง `username` | 38 |
| จุดที่อ้าง `X-User-Id` / gateway | 339 |
| migration เดิมที่ห้ามแตะ | 9 |
| endpoint ที่กระทบ | 68 |

และ `data-dictionary.md` ข้อ 9.3 **ห้ามลบหรือ squash migration เดิม** กับ
**ห้ามให้ Prisma สร้าง drop+add ตอนเปลี่ยนชื่อคอลัมน์** ต้องเขียน
`ALTER TABLE ... RENAME COLUMN` เองพร้อม rename index/constraint
ไม่งั้นข้อมูลหาย

## 4. ตัวมาตรฐานเองขัดกันอยู่ 4 จุด — ต้องให้ PL/PM ชี้ขาด

README ของ standards เขียนไว้เองว่า *"ถ้าสองอย่างขัดกันให้ยึด `contracts/`
แล้วแจ้ง PL ทันที"* ต่อไปนี้คือสิ่งที่เจอ **ทุกข้อกระทบงานเราโดยตรง**

### 4.1 npm หรือ pnpm — ขัดกันสามทาง

| แหล่ง | บอกว่า |
| --- | --- |
| `contracts/vocabulary.json` | `"packageManager": "npm (ต้อง commit package-lock.json)"` |
| `docs/tech-stack.md` ข้อ 1.1 | **pnpm** · ห้ามมี `package-lock.json` |
| `scripts/check-qa.sh` (QA-05) | ตีตกถ้าพบ `package-lock.json` |

ตามกฎ "ยึด contracts" เราทำถูกอยู่แล้ว แต่ CI จะตีตกเรา
**ต้องได้คำตอบก่อนย้าย** เพราะการย้ายไป pnpm กระทบ lockfile ทั้ง repo

### 4.2 `username` ห้ามใช้หรือใช้ได้

| แหล่ง | บอกว่า |
| --- | --- |
| `data-dictionary.md` ข้อ 9.2 | `username` **อยู่ในรายชื่อต้องห้าม** |
| `data-dictionary.md` Errata | *"มติ: ยึด `username`"* ← ขัดกับข้อ 9.2 ในเอกสารฉบับเดียวกัน |
| `scripts/check-field-aliases.sh` | รายการต้องห้าม **ไม่มี** `username` |
| `schemas/user.schema.json` | `required: ["username", "layer1_role"]` |

บล็อก Errata ยังอ้าง *"gateway ออก token ด้วยชื่อนี้"* ซึ่งขัดกับ
`auth-contract.md` ที่บอกว่าไม่มี gateway — ดูเหมือนเป็นข้อความค้างจากฉบับเก่า
ที่ลืมลบ

> หมายเหตุ: ต่อให้ชี้ขาดว่า `username` ใช้ได้ **เราก็ยังต้องเปลี่ยนคีย์อยู่ดี**
> เพราะเหตุผลในหัวข้อ 3 คือ token ไม่ส่ง `username` มาให้ ไม่ใช่เพราะ linter

### 4.3 `schemas/user.schema.json` ล้าสมัย

ยังบังคับ `username` + `layer1_role` + `faculty_code` และ enum ของ role
มี `faculty` กับ `guest` เพิ่มมา ทั้งที่ `data-dictionary.md` ข้อ 1.3 บอกชัดว่า
`faculty` **ยังไม่มีใน Core Hub v1.0** และ `vocabulary.json` ระบุ core role
แค่ 4 ค่า (`student` `alumni` `staff` `admin`)

### 4.4 เข้าถึง reference implementation ไม่ได้

เอกสารสั่งให้ *"คัดลอกชั้น auth จาก reference implementation"* และ SEC-04
ก็แนะนำแบบเดียวกันตอนตีตก แต่ `github.com/CSMJU2030/demo-student-subsystem`
**ตอบ 404** — ขอสิทธิ์เข้าถึง หรือขอให้เปิดเป็น public

## 5. แผนการย้าย — เรียงตามลำดับที่ต้องทำจริง

แต่ละระยะจบในตัวและตรวจได้ ไม่ใช่รื้อทั้งหมดพร้อมกัน

### ระยะ 0 — ถามให้ได้คำตอบก่อน (ไม่ต้องเขียนโค้ด)

ข้อ 4.1 (npm/pnpm) · ข้อ 4.2 (`username`) · ข้อ 4.4 (สิทธิ์ reference)
**ทั้งสามข้อเปลี่ยนวิธีทำงานของระยะถัดไป ถ้าเดาผิดต้องทำซ้ำ**

### ระยะ 1 — ของถูกและเสี่ยงต่ำ (ทำได้เลย ไม่กระทบสถาปัตยกรรม)

(`SEC-01` ไม่อยู่ในรายการเพราะเป็นผลบวกลวง — ดูหัวข้อ 2)

- `GH-04` เพิ่ม `.standards-version` + ผูก `standards/` เป็น submodule
- `API-02` ตั้ง global prefix `api` และยกเว้น `GET /auth/callback`
- `DD-03` ใส่ `@map` ให้ฟิลด์ camelCase ทุกตัว (พร้อม migration RENAME)
- `DD-01` แก้คอมเมนต์ที่มีคำว่า `user_id`

### ระยะ 2 — ชั้น auth ใหม่ (หัวใจของงาน)

เขียน `backend/src/auth/` ตามโครงที่ `repo-structure.md` ข้อ 2 กำหนด:
`jwks.service.ts` · `core-hub-token.verifier.ts` · `guards/` · `decorators/` ·
`role-mapping.ts` · `permissions.ts` · `sso-callback.controller.ts` ·
`me.controller.ts`

ใช้ `jose` ตรวจครบ 8 ขั้น · แคช JWKS 10 นาที · เลือกกุญแจด้วย `kid` ·
รีเฟรชครั้งเดียวเมื่อเจอ `kid` แปลก · จำกัดอัตรา 30 วินาทีต่อครั้ง

**ทิ้ง `X-User-Id` ทั้งหมด** และลบด่าน `GATEWAY_SHARED_SECRET`
ที่ไม่มีความหมายอีกต่อไป

### ระยะ 3 — เปลี่ยนคีย์ตัวตนเป็น `core_user_id`

งานใหญ่ที่สุด กระทบ 84 ไฟล์ · 68 endpoint · ทุกตาราง
ต้องเขียน migration แบบ RENAME COLUMN เอง ห้ามให้ Prisma drop+add

### ระยะ 4 — รูปแบบ API

`per_page` เป็น `limit` · meta เป็น `{total, page, limit, totalPages}` ·
JSON เป็น camelCase · `GET /api/health` · `GET /api/v1/me`

### ระยะ 5 — โครง repo และ dependency

ย้ายหน้าบ้านจากรากไปที่ `frontend/` · ตัด dependency ที่ไม่อยู่ใน whitelist
หรือเปิด issue ขอเพิ่ม · จัดการ npm/pnpm ตามคำตอบข้อ 4.1

> **`socket.io` ไม่อยู่ใน whitelist** ซึ่งเป็นปัญหาใหญ่เงียบ ๆ เพราะแชท
> การแจ้งเตือน ห้องเสียง และสายเรียกเข้า **ทั้งหมดวางอยู่บนมันหมด**
> ต้องเปิด issue ขอเพิ่มพร้อมเหตุผลตั้งแต่วันนี้ ไม่ใช่รอถึงระยะ 5
> แล้วค่อยรู้ว่าขอไม่ผ่าน

| `layer1-roles.decorator.ts` | อ่าน role จาก header แทน claim |

เก็บไว้ปรับได้: `layer2-roles.decorator.ts` · `member-role.ts` ·
`public.decorator.ts` · `roles.guard.ts`

ของใหม่ที่ต้องสร้าง (`backend/src/auth/` ตาม `repo-structure.md` ข้อ 2):

```

permissions.ts               <resource>:<action>[:own|:any]
sso-callback.controller.ts   GET /auth/callback (นอก prefix /api)
me.controller.ts             GET /api/v1/me
```

### ข. เส้นทางบังคับ 3 เส้น — ขาด 2 เส้น มีผิดที่ 1 เส้น

| ต้องมี | สถานะตอนนี้ |
| --- | --- |
| `GET /api/health` | มี `/health` — **ผิดที่ ต้องย้าย** |
| `GET /api/v1/me` | **ไม่มี** (มีแต่ `/profiles/me` กับ `/members/me`) |
| `GET /auth/callback` | **ไม่มีเลย** |

`backend/src/main.ts` ยังไม่ได้เรียก `setGlobalPrefix('api')` เลย —
ตอนนี้แต่ละ controller เขียน path เอง

### ค. env ที่มาตรฐานบังคับ — ขาด 5 ตัวจาก 7

`backend/.env.example` มี `PORT` กับ `DATABASE_URL` แล้ว
**ขาด:** `CORE_HUB_URL` · `CORE_HUB_JWKS_URL` · `CORE_HUB_ISSUER` ·
`CORE_HUB_AUDIENCE` · `SUBSYSTEM_ID`

และต้อง**ลบ** `GATEWAY_SHARED_SECRET` · `ALLOW_UNPROTECTED_GATEWAY` ·
`DEV_FAKE_GATEWAY` ออก (ทั้งใน `.env.example`, `main.ts` และ `render.yaml`)
เพราะไม่มี Gateway ให้พิสูจน์ตัวอีกแล้ว

### ง. รูปแบบ response — แก้ที่ 3 ไฟล์ กระทบ 68 endpoint

`backend/src/common/http/envelope.ts`

| ตอนนี้ | ต้องเป็น |
| --- | --- |
| `current_page` | `page` |
| `per_page` | `limit` |
| `total_pages` | `totalPages` |
| `total_items` | `total` |

`backend/src/common/http/pagination.dto.ts` — query `?per_page=` เป็น `?limit=`
(ค่าเริ่มต้น 20 สูงสุด 100)

`backend/src/common/http/http-exception.filter.ts` — รหัสข้อผิดพลาดตอนนี้เป็น
ตัวพิมพ์เล็ก (`not_found`, `internal_error`) แต่ `contracts/error-codes.json`
เป็น **enum ปิด ตัวพิมพ์ใหญ่** 7 ค่าเท่านั้น:
`BAD_REQUEST` `VALIDATION_ERROR` `UNAUTHORIZED` `FORBIDDEN` `NOT_FOUND`
`CONFLICT` `INTERNAL_ERROR`

> `VALIDATION_ERROR` ต้องมี `error.details` เป็น array ของข้อความด้วย

และ JSON ทุก field ต้องเป็น **camelCase** (`vocabulary.json`) ยกเว้น 5 คำ
ที่เป็น snake_case ได้: `access_token` `token_type` `expires_in`
`callback_url` `state` — ตอนนี้เราใช้ snake_case ทั้งระบบ

### จ. schema — 101 ฟิลด์ใน 24 ตาราง ต้องใส่ `@map`

`backend/prisma/schema.prisma` — ตารางที่กระทบมากที่สุด:

```
Message 10 · Asset 8 · SubsystemMember 7 · Report 6 · Reel 6
Meeting 5 · AuditLog 5 · Story 4 · ReelComment 4 · PostComment 4
Post 4 · Notification 4 · และอีก 12 ตาราง
```

`@@map` ระดับตารางมีครบแล้ว ขาดแค่ `@map` ระดับคอลัมน์
