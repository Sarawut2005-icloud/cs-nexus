## 2. งานที่เสร็จแล้วรอบนี้

ทุกข้อทดสอบกับ Core Hub ตัวจริง ด้วยเบราว์เซอร์จริงสองเครื่องที่ล็อกอินคนละบัญชี ไม่ใช้ข้อมูลปลอม

### 2.1 ต่อกับ Core Hub และตัวตนจริง (26–28 ก.ย.)

- ล็อกอินผ่าน Core Hub SSO ครบทุกขั้น: login → handoff → callback → cookie → `/me`
- เปลี่ยนคีย์ตัวตนจาก `username` เป็น `coreUserId` ทั้งระบบ (25 คอลัมน์ 84 ไฟล์) ด้วย migration แบบ `RENAME COLUMN` ข้อมูลเดิมไม่หาย
- ลบโมดูลตัวตนปลอมออกหมด
- token หมดอายุแล้วพากลับเข้า SSO เอง ไม่โชว์ข้อความผิดพลาดดิบให้ผู้ใช้เห็น
- เปิดโหมดมืดที่เคยตั้งค่าไว้แต่ใช้งานไม่ได้

### 2.2 โทร แชร์หน้าจอ และวิดีโอคอล (28–29 ก.ย.)

| ฟีเจอร์ | ผลทดสอบ |

บั๊กที่เจอและแก้แล้ว:

- **ปุ่มโทรในแชทส่วนตัวกดไม่ได้เลยทุกห้อง** เพราะหน้าบ้านไม่รู้ว่าคู่สนทนาคือใคร แก้โดยให้หลังบ้านส่ง `peer_core_user_id` มาให้
- ผู้รับสายแชร์หน้าจอแล้วผู้โทรไม่เห็นภาพ เพราะวิธีเจรจา WebRTC แบบเดิมผิดสเปก เปลี่ยนไปใช้ perfect negotiation
- ภาพที่แชร์ในสายโทรไม่เคยถูกแสดงบนหน้าจอเลย
- ห้องเสียงบางคู่ต่อสายไม่ติด ขึ้นกับลำดับตัวอักษรของ id ผู้ใช้
- หยุดแชร์จากแถบของเบราว์เซอร์แล้วอีกฝ่ายยังเห็นภาพค้าง
- TURN server ใช้ไม่ได้ เพราะชื่อฟิลด์ `username` ถูกเปลี่ยนไปตอนย้ายคีย์ตัวตน

## 3. แผนงานต่อไป (คัดตามมาตรฐาน CSMJU2030)

คัดจากรายการข้อเสนอ ด้วยเกณฑ์จากมาตรฐาน:

- `tech-stack.md` ข้อ 1: ใช้ได้เฉพาะ Next.js, NestJS, PostgreSQL (ผ่าน Prisma) และ Docker ห้ามใช้ฐานข้อมูลตัวอื่น
- `tech-stack.md` ข้อ 1.4 (กฎ `ARC-02`): ไลบรารีที่ไม่อยู่ใน `allowed-deps.json` ต้องเปิด issue ขอ DevOps ก่อน แก้รายการเองไม่ได้
- `api-conventions.md` ข้อ 9: ยังไม่มีสัญญาให้ระบบย่อยเรียกหากัน และยังไม่มี API Gateway
- งบประมาณ 0 บาท ใช้บริการที่ไม่ต้องผูกบัตรเท่านั้น

### 3.1 ทำได้ทันที (ตรงมาตรฐาน ไม่ต้องขออนุมัติ)

| ลำดับ | งาน | เหตุผล |
|---|---|---|
| 1 | **Dockerfile และ `docker-compose.yml` ที่ root** | มาตรฐานบังคับ (`tech-stack.md` ข้อ 1.1 และ 2) ตอนนี้มีแค่ `backend/docker-compose.yml` สำหรับฐานข้อมูล ยังไม่มี Dockerfile ของแอป |
| 2 | ค้นหาเร็วขึ้นด้วย `pg_trgm` ของ PostgreSQL | ตอนนี้ค้นด้วย `ILIKE '%คำ%'` ซึ่งอ่านทั้งตาราง พอข้อมูลเยอะจะช้า `pg_trgm` อยู่ใน PostgreSQL อยู่แล้ว ไม่ต้องเพิ่มไลบรารี |
| 3 | จำกัดความถี่การเรียก API (กันสแปม) | ยังไม่มี API Gateway มาช่วย ระบบย่อยต้องป้องกันเอง เขียนเป็น guard ของ NestJS ได้โดยไม่ต้องเพิ่มไลบรารี |
| 4 | ย้ายเทสต์เบราว์เซอร์จริงเข้า repo | สคริปต์ที่ใช้ทดสอบรอบนี้ไม่ต้องลงไลบรารีเพิ่ม (ใช้ Chrome DevTools Protocol ตรง) จึงเก็บเข้า `test/e2e/` และรันใน CI ได้เลย |
| 5 | สคริปต์สำรองฐานข้อมูลรายวันและสคริปต์กู้คืน | ใช้ `pg_dump` ซึ่งมาพร้อม PostgreSQL |
| 6 | ส่งออกข้อมูลส่วนตัวตาม PDPA | ส่งออกได้เฉพาะข้อมูลที่ระบบนี้เก็บเอง (กระทู้ ข้อความ ไฟล์) ส่วนการลบบัญชีเป็นหน้าที่ของ Core Hub ระบบนี้ทำได้แค่ลบหรือปิดบังข้อมูลของตัวเอง |
| 7 | หยุดวิดีโอเมื่อผู้ใช้สลับแท็บ | ใช้ API ของเบราว์เซอร์ (`visibilitychange`) ช่วยประหยัดแบตและเน็ต |
| 8 | คู่มือใช้งานสำหรับนักศึกษาและอาจารย์ | เป็นเอกสาร ไม่กระทบโค้ด |

**มีอยู่แล้ว ไม่ต้องทำเพิ่ม:**

- หน้าเอกสาร API แบบกดทดสอบได้ (Swagger UI) ที่ `/api/docs`
- สตอรี่หมดอายุใน 24 ชั่วโมง พร้อมตัวลบอัตโนมัติ
- ตัวลบไฟล์ที่อัปโหลดค้างแต่ไม่ได้ใช้ ทำงานทุก 30 นาที
- บันทึกการทำงานของแอดมิน (ตาราง `AuditLog` บันทึกอยู่ 12 จุด)

### 3.2 ต้องขออนุมัติ PM/DevOps ก่อน

| งาน | สิ่งที่ต้องขอ | ความจำเป็นตอนนี้ |
|---|---|---|
| แปลงไฟล์วิดีโอเบื้องหลัง (FFmpeg + คิวงาน) | Redis, BullMQ และ FFmpeg ไม่อยู่ในมาตรฐาน | ปานกลาง เมื่อคลิปมีมากขึ้น |
| ย้ายไฟล์ไปเก็บบน cloud พร้อม CDN | ต้องเลือกผู้ให้บริการที่ฟรีโดยไม่ผูกบัตร (Cloudflare R2 ต้องผูกบัตร Supabase Storage ไม่ต้อง) | สูง เมื่อขึ้นระบบจริง เพราะตอนนี้เก็บไฟล์บนดิสก์เครื่องเซิร์ฟเวอร์ |
| แจ้งเตือนนอกแอป (Web Push) | ไลบรารี `web-push` | ปานกลาง |
| ติดตาม error และประสิทธิภาพ (Sentry, Prometheus) | ไลบรารีไม่อยู่ในรายการ ระหว่างนี้ใช้ structured log ตาม `logging.md` | ต่ำ |
| ห้องเสียงเกิน 8 คน (SFU เช่น LiveKit) | ต้องมีเซิร์ฟเวอร์สื่อเพิ่มและไลบรารีใหม่ | ต่ำ ห้องเรียนกลุ่มย่อยยังไม่เกิน 8 คน |
| วัดการใช้งาน (PostHog, Umami) | บริการภายนอกที่เก็บพฤติกรรมผู้ใช้ ต้องผ่านเรื่อง PDPA ก่อน | ต่ำ |
| ทดสอบรับโหลด socket 1,000 คนขึ้นไป (k6) | เป็นโปรแกรมแยก ไม่ใช่ไลบรารีในแอป แต่ควรแจ้ง DevOps ก่อนยิงโหลดใส่เซิร์ฟเวอร์ร่วม | ต่ำ |

### 3.3 ยังไม่ทำ (ขัดมาตรฐานหรือเกินขอบเขต)

| งาน | เหตุผล |
|---|---|
| Elasticsearch / Meilisearch | เป็นฐานข้อมูลอีกตัว มาตรฐานให้ใช้ PostgreSQL อย่างเดียว ใช้ `pg_trgm` แทน (ข้อ 3.1) |
| RabbitMQ / NATS | อยู่นอกมาตรฐาน และยังไม่มีสัญญาให้ระบบย่อยคุยกันเอง |
| Bot SDK / Webhook ให้คนนอกต่อเข้ามา | ยังไม่มีสัญญาการเรียกข้ามระบบ ต้องเสนอผ่าน Change Process ก่อน |
| เข้ารหัสแชทส่วนตัวปลายทางถึงปลายทาง (E2EE) | ทำให้ระบบรายงานเนื้อหาไม่เหมาะสมกับการค้นหาใช้ไม่ได้ และยังไม่มีมาตรฐานการจัดการกุญแจ |
| สตรีมวิดีโอแบบปรับความละเอียดอัตโนมัติ (HLS/DASH) | ต้องมีระบบแปลงไฟล์ก่อน และคลิปสั้นยังไม่จำเป็น |
| ฟีเจอร์ AI (สรุปแชท ซับไตเติลอัตโนมัติ ค้นหาด้วยความหมาย คัดกรองเนื้อหาอัตโนมัติ) | มีค่าใช้จ่าย ต้องส่งข้อมูลนักศึกษาออกไปให้บริการภายนอก (PDPA) และ `pgvector` ไม่อยู่ในมาตรฐาน |
| ฐานข้อมูลสำรองแยกอ่าน-เขียน (read replica) และ Helm Charts | เกินขนาดของระบบตอนนี้ มาตรฐานกำหนดแค่ Docker compose |
